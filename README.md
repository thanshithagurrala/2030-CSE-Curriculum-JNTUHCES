## 3. Foundation vs Current Relevance

I checked important core subjects and gave each one a decision.

| Course | Decision | My reason |
|---|---|---|
| CS302PC Data Structures | KEEP | Still important for software development and technical interviews. |
| CS305PC OOP through Java | UPDATE | Keep OOP, but update old Java content and add current tools, testing and version control. |
| CS403PC Operating Systems | UPDATE | Keep OS concepts and connect them with containers, virtualization and modern deployment. |
| CS404PC DBMS | UPDATE | Keep SQL and database foundations, with practical APIs and modern database awareness. |
| CS501PC DAA | KEEP | Algorithms and complexity are still important for software development and interviews. |
| CS502PC Computer Networks | UPDATE | Keep networking foundations and add practical HTTP, API, cloud and service communication examples. |
| CS503PC DevOps | UPDATE | Connect DevOps with cloud, containers, CI/CD, monitoring and cloud-native development. |
| CS601PC Machine Learning | UPDATE | Keep ML foundations and add modern Python practice, evaluation and responsible AI. |
| CS603PC Artificial Intelligence | UPDATE | Keep AI foundations and connect them with GenAI, LLM applications, agents and verification. |
| CS701PC Cryptography and Network Security | UPDATE | Keep security foundations and add modern application and software supply-chain security. |

My main conclusion is that foundation topics should not simply be removed. Selected content should be updated and connected with practical work.

## 4. What Changed in 2026

I checked current technology and industry sources and found these changes:

1. Generative AI became mainstream — affects CS601PC and CS603PC.
2. AI-assisted software development became common — affects CS305PC, CS501PC, CS503PC, CS601PC and CS603PC.
3. AI agents became an emerging software development area — affects CS603PC and CS503PC.
4. Kubernetes and cloud-native development became important for production workloads — affects CS503PC.
5. The Java ecosystem moved to newer LTS releases — affects CS305PC.
6. Software supply-chain security became a stronger concern — affects CS701PC and CS503PC.
7. Responsible and trustworthy AI became more important — affects CS601PC and CS603PC.
8. Python adoption increased strongly in current development and AI/data work — affects CS601PC and CS603PC.

## 5. Curriculum vs Industry

I compared the curriculum with three real graduate/early-career software job descriptions.

### Amazon – Graduate Software Development Engineer
Expected skills include programming, data structures, algorithms, OOP, cloud, SQL/NoSQL, version control, debugging, SDLC, AI-assisted development, CI/CD, monitoring and cloud-native development.

**R22 match:** Good foundation.  
**Gap I noticed:** These skills are present in separate subjects but are not always connected into one end-to-end workflow.

### Amgen – Associate Software Engineer, Full Stack
Expected skills include React, TypeScript/JavaScript, Python, SQL, REST APIs, cloud-native development, microservices, Docker, Kubernetes, Git, Agile, CI/CD, testing, observability, security and AI/GenAI applications.

**R22 match:** Many related topics exist.  
**Gap I noticed:** Students need more connected practice from application development through testing, deployment and monitoring.

### WRI India – Program Associate / Software Engineer
Expected skills include React/Vue, Python/Node.js, PostgreSQL/PostGIS, REST APIs, Git/GitHub, Agile, AWS/GCP, Docker, CI/CD, AI/ML tools, LLM APIs and prompt engineering.

**R22 match:** Several foundations are available.  
**Gap I noticed:** Practical full-stack, deployment, AI integration and portfolio-level work need stronger connection.

**My conclusion:** R22 gives a good foundation, but industry expects students to combine these skills and actually build, test and deploy software.

## 6. My 2030 Curriculum

I kept the degree at **160 credits** and did not simply add subjects on top of the existing workload.

Main changes:

- Modernize programming and developer tools.
- Keep Statistics before Machine Learning.
- Strengthen the path ML → AI → Deep Learning → NLP → GenAI/LLM applications.
- Add a Deep Learning core course and lab.
- Add a small Prompt Engineering and AI-assisted Development component.
- Strengthen NLP.
- Strengthen Cyber Security and security practice.
- Connect DevOps with Cloud.
- Add Cloud-Native and Distributed Systems practice.
- Add GenAI and LLM Applications.
- Add AI/ML Engineering Practice.
- Strengthen testing and secure software development.
- Connect subjects through practical projects.

### Learning paths

**AI path:** Programming → Statistics → Machine Learning → Artificial Intelligence → Deep Learning → NLP → Generative AI and LLM Applications

**Software path:** Programming → OOP → Software Engineering → Full Stack Development → DevOps and Cloud → Cloud-Native Development → Project

### Credit balance

R22 = 160 credits  
2030 proposal = 160 credits

20% of 160 = 32 credits  
25% of 160 = 40 credits

My proposed redesign is approximately **36 credits**, which is **22.5%** of the degree, within the requested 20–25% range.

My first change would be:

**DevOps & Cloud – 4 credits**

Funded by restructuring:
- CS503PC DevOps – 3 credits
- CS505PC DevOps Lab – 1 credit

Other changes use existing AI/ML, elective, lab, project and older/repeated-content space rather than increasing the total degree credits.

## 7. What Would Make Me Wrong?

### 7a. Evidence that could disprove my proposal

My proposal could be wrong if:

- Current graduate jobs do not require the modern skills I identified.
- Employers say R22 already prepares students well.
- The proposed curriculum creates too much workload.
- R25 already solves the main problems better than my proposal.
- Real testing shows that some proposed skills are not useful enough to justify curriculum space.

### 7b. One belief I changed

At first, I thought the main problem was that students need more AI subjects.

After checking R25 and current industry evidence, I changed my view. AI is already being added to the curriculum. I now think the bigger requirement is **strong CSE foundations plus modern AI, software development, cloud, security and practical skills**.

### 7c. What I could not verify

I could not verify:

- Actual internal lab grading rubrics and marks.
- The exact software setup used for every college lab.
- Direct employer feedback from my own college.
- Whether AI-generated Java, LEX and DBMS answers would pass the original lab environment without testing.
- A completed 20-minute faculty/recent-graduate interview.

I have not created a fake interview or claimed that untested AI code definitely passes.

### AI experiment

I tested actual coursework from five subjects using **GPT-5.6 Luna on 14 September 2026**:

- Cryptography and Network Security – RSA calculation
- Machine Learning – K-Means explanation
- Compiler Design – LEX program
- Java – calculator GUI
- DBMS – trigger examples

The experiment showed that AI can explain concepts, solve some problems and generate code, SQL and LEX programs. But generated answers still need checking, compiling, execution, testing and debugging.

One AI claim I found weak was the idea that an AI-generated Java/LEX/DBMS solution can automatically be treated as a correct or passing lab answer. I could not verify that without running it in the actual environment.

### Final finding

The R22 curriculum has strong foundations, but selected subjects need targeted updates so students graduating in 2030 can connect those foundations with modern AI, software development, cloud, security, testing and practical engineering work.
